# MAESTRO Threat Model Mapping: ChangSupport.AI

This threat model uses the CSA **MAESTRO** framework (Multi-Agent Environment, Security, Threat, Risk and Outcome), which has seven layers. For each layer it lists the ChangSupport.AI components, the main threats (with their OWASP LLM Top 10 / OWASP Agentic AI Top 10 risk IDs, matching [redteam/plan.md](../redteam/plan.md)), the controls in place, and the red team suites that exercise them.

**Trust boundary.** The LLM, retrieved policy text and customer input are all **untrusted**. The guardrail ([app/guardrails.py](../app/guardrails.py)) is the only component allowed to move money, change a case to a final status, or approve a tool call. It is deterministic code and contains no model.

**Assets.** The assets are the company's money (the mock bank), customer PII and order history, the integrity of case decisions, and the integrity of the audit log.

## Layer 1: Foundation Models

|                   |                                                                                                                                                                                                                                                                                   |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Components**    | LLM in [app/llm.py](../app/llm.py): `MockLLM` (default, deliberately injectable) or `OllamaLLM` (local Qwen). Either one proposes APPROVE/DENY and an amount                                                                                                                      |
| **Threats**       | Direct prompt injection in the refund reason (LLM01/ASI01); indirect injection through retrieved text (LLM01/ASI01); hallucinated amounts or made-up policy rules (LLM07); revealing the system prompt or hidden instructions (LLM08); being talked out of business rules (LLM01) |
| **Controls**      | The model's output is only a _proposal_. The guardrail checks it against the case amount (`AMOUNT_MISMATCH`), the order total, the $100 cap and the $500 weekly cap. The model has no direct access to tools                                                                      |
| **Red team**      | RT-01 (hidden command in refund reason), RT-02 (reveal hidden instructions), RT-03 (made up policy rule)                                                                                                                                                                          |
| **Residual risk** | The return-window and digital-goods rules are judged by the model, so they can be bypassed (finding RT-01-c). Losses are limited by the caps                                                                                                                                      |

## Layer 2: Data Operations

|                   |                                                                                                                                                                                                                                                                                                       |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Components**    | SQLite customer, order and case records; policy store, retriever and ChromaDB vector index ([app/retriever.py](../app/retriever.py), [app/vector_store.py](../app/vector_store.py))                                                                                                                   |
| **Threats**       | Cross-customer reads and writes (LLM02/ASI03); data leaving the system by email (LLM02); RAG poisoning through an uploaded policy (ASI06); hidden instructions inside an uploaded policy (LLM01/ASI01); semantic evasion of retrieval, such as pulling up a lookalike customer's record (LLM09/LLM02) |
| **Controls**      | Ownership checks on every records, case, bank and email tool call (`IDENTITY_PRIVILEGE_MISMATCH`); email can only go to the case owner's address on file; only admins can upload policies, and the uploader is recorded                                                                               |
| **Red team**      | RT-04 (fake policy upload), RT-05 (another customer's record), RT-13 (injection in an uploaded policy), RT-14 (lookalike record retrieval)                                                                                                                                                            |
| **Residual risk** | Policy content isn't screened, so a poisoned policy can sway the model (findings RT-04-a, RT-13-a)                                                                                                                                                                                                    |

## Layer 3: Agent Frameworks

|                   |                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Components**    | Orchestrator and the five specialists ([app/agent.py](../app/agent.py)); tool registry ([app/tools/](../app/tools/))                                                                                                                                                                                                                                                                                                                            |
| **Threats**       | Goal hijacking (ASI01); a specialist calling tools outside its role (ASI02); an agent changing its own permissions (LLM03); a refund larger than the order price or not linked to a case (LLM03/ASI03); a forged "already verified" or "supervisor approved" message passed between agents (ASI07/ASI03); an agent bypassing a supervisor decision (ASI03); one agent's mistake cascading into wrong decisions and emails down the line (ASI08) |
| **Controls**      | Per-agent tool allowlist, held in an immutable `MappingProxyType` of `frozenset`s (`PERMISSION_DENIED`); unknown tools are blocked (`UNKNOWN_TOOL`); agents can't set `APPROVED` without a payout or decide `ESCALATED` cases (`SUPERVISOR_DECISION_REQUIRED`); finalized cases can't be changed (`CASE_FINALIZED`)                                                                                                                             |
| **Red team**      | RT-06 (refund larger than the order), RT-07 (fake "already approved" claim)                                                                                                                                                                                                                                                                                                                                                                     |
| **Residual risk** | None currently open                                                                                                                                                                                                                                                                                                                                                                                                                             |

## Layer 4: Deployment Infrastructure

|                   |                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Components**    | FastAPI service ([app/main.py](../app/main.py)), SQLite file, kill-switch setting, Ollama-hosted model, MCP tools and mock APIs                                                                                                                                                                                                                                                                                          |
| **Threats**       | The agent keeps acting after revocation, or requests race the kill switch (ASI10); identity is spoofed through the request body (ASI03); calling the bank or refund API directly, skipping the agent's checks (ASI03/ASI02); malicious tool inputs that execute code on the server (LLM10/ASI05); a compromised Python dependency or MCP package (LLM04/ASI04); request floods that exhaust the model or backend (LLM06) |
| **Controls**      | The kill switch is checked on _every_ tool call and again inside the payout transaction, and it fails closed. Identity comes only from the `X-API-Key` header, and a mismatched body `customer_id` gets `403`. Role-based endpoint access. Model calls time out (`OLLAMA_TIMEOUT`, 30 s by default)                                                                                                                      |
| **Red team**      | RT-08 (calling the bank API directly), RT-09 (request flood), RT-15 (malicious tool inputs), RT-16 (compromised dependency)                                                                                                                                                                                                                                                                                              |
| **Residual risk** | API keys are static mock values; a real deployment needs real authentication (OIDC/mTLS) and secret storage. There is no request rate limiting yet                                                                                                                                                                                                                                                                       |

## Layer 5: Evaluation & Observability

|                   |                                                                                                                                                                                                                                                                                                   |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Components**    | Audit log ([app/audit.py](../app/audit.py)), `/logs`, `/logs/verify`, red team runner ([app/redteam.py](../app/redteam.py))                                                                                                                                                                       |
| **Threats**       | Actions that go unlogged (ASI02); tampering with the log after the fact (ASI03); malicious text in logged customer requests later retrieved as trusted context (ASI06); sensitive customer data stored in or exposed through logs (LLM02); salami-slicing that only shows up in aggregate (LLM03) |
| **Controls**      | Every tool call and decision is logged with a SHA-256 hash chain, and `verify_chain` finds the first altered entry. The weekly cap is computed from the ledger. Every red team run is logged and its evidence saved                                                                               |
| **Red team**      | RT-10 (attack leaves no trace), RT-17 (edit/delete decision logs), RT-18 (injection into activity logs), RT-19 (sensitive data in logs); the audit chain is checked after every attack                                                                                                            |
| **Residual risk** | The log lives in the same database as the app; a real deployment should ship it to append-only external storage                                                                                                                                                                                   |

## Layer 6: Security & Compliance

|                   |                                                                                                                                                                                                                                                                                                                                                                                                |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Components**    | Guardrail ([app/guardrails.py](../app/guardrails.py)), disbursement ledger                                                                                                                                                                                                                                                                                                                     |
| **Threats**       | Payouts above the cap, including many small refunds that exceed the weekly limit (LLM03); tampered or negative amounts; paying the same order twice; races between checks and payouts; refunds continuing after the kill switch (ASI10); a supervisor manipulated into approving an unauthorized refund (ASI09); an admin using supervisor functions or a supervisor changing policies (ASI03) |
| **Controls**      | Hard-coded limits ($100 per transaction, $500 per week) that agents can't change; checks for amount validity, amount ≤ order total, and amount already refunded per order; the check and payout run in one `BEGIN IMMEDIATE` transaction; the ledger is written only by the guardrail                                                                                                          |
| **Red team**      | RT-20 (weekly cap), RT-21 (kill switch), RT-22 (manipulating the supervisor), RT-24 (admin using supervisor functions), RT-25 (supervisor modifying policies)                                                                                                                                                                                                                                  |
| **Residual risk** | None currently open in this layer 7                                                                                                                                                                                                                                                                                                                                                            |

## Layer 7: Agent Ecosystem

|                   |                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Components**    | Customers, supervisors and admins; external systems behind the tools (bank, email)                                                                                                                                                                                                                                                                                                                                                              |
| **Threats**       | A customer pretending to be another customer (ASI03); customers abusing an autonomous approver, such as resubmitting for duplicate refunds (ASI08); a malicious request that tricks the Intake agent into fetching unrelated records (ASI01); a forged message claiming another agent already verified the customer (ASI07); an over-trusting supervisor (ASI09); a malicious admin uploading a policy (ASI06); compromised tools (LLM04/ASI04) |
| **Controls**      | Three separate roles with different keys; escalated cases go to a human; supervisor decisions are logged with the supervisor's ID and comment; all external effects go through a mock tool behind the guardrail                                                                                                                                                                                                                                 |
| **Red team**      | RT-11 (pretending to be another customer), RT-12 (duplicate refund), RT-23 (Intake fetching unrelated records)                                                                                                                                                                                                                                                                                                                                  |
| **Residual risk** | Policy uploads and large supervisor approvals are not double checked; a second reviewer should approve these before they take effect                                                                                                                                                                                                                                                                                                            |

## Cross-layer summary

| Threat                                | Layers  | Primary control                                  | Status                      |
| ------------------------------------- | ------- | ------------------------------------------------ | --------------------------- |
| Prompt injection → over-cap payout    | L1 → L6 | Caps and amount checks in the guardrail          | Defended                    |
| Prompt injection → policy-rule bypass | L1 → L2 | _(none yet; left to the model)_                  | **Finding**                 |
| Cross-customer access                 | L2, L6  | Ownership checks on every tool                   | Defended                    |
| Over-privileged agent                 | L3      | Immutable allowlist                              | Defended                    |
| Action after revocation               | L4, L6  | Fail-closed kill switch on every call            | Defended                    |
| Salami slicing                        | L5, L6  | Ledger-based weekly cap, atomic check and payout | Defended                    |
| RAG poisoning                         | L2, L7  | Admin-only upload, still capped by the guardrail | **Finding** (below the cap) |
| Log tampering                         | L5      | Hash chain + `/logs/verify`                      | Detected                    |
| Request flooding                      | L4      | Model call timeout only                          | **Open** (no rate limiting) |
